# 연습장 디자인 개편 계획서 — Material Design 3 (Expressive)

> 작성 2026-11-04 · 대상: `web/` 연습장(대전·훈련·복기·전적) · 현재: 빌드 없는 바닐라 JS + 직접 쓴 CSS
> 목표: **앱처럼 예쁘고 깔끔한 M3 느낌**, **누구나 쉽게 모든 기능을 쓰는 UX**, **60fps 애니메이션**, **개발 속도**를 같이 잡는다.
> 변경 2026-11-04: §6 UX 설계(버튼 배치·정보 표시·흐름·온보딩·검증) 추가, 단계별 UX 과제와 완료 기준 반영

## 1. 결론 먼저

| 층 | 선택 | 한 줄 이유 |
|---|---|---|
| UI 프레임워크 | **Svelte 5 + SvelteKit(정적 빌드)** + TypeScript | 컴파일러라 런타임이 작고 빠르다. 카드가 손패→버림패→바닥으로 움직이는 게임 화면에 맞는 **전환·FLIP 애니메이션이 내장**돼 있다 |
| M3 컴포넌트 | **직접 만든 M3 컴포넌트 키트** (토큰 기반) + 접근성은 **브라우저 기본 요소**(`<dialog>`, `popover`) | 공식 Material Web은 유지보수 모드라 신규 기능(Expressive)이 없다. 필요한 15개 남짓만 토큰으로 만들면 M3 충실도와 번들 크기를 둘 다 잡는다 |
| 색·테마 | **@material/material-color-utilities** (시드 색 → 톤 팔레트 → 라이트/다크/고대비) | M3 동적 색 알고리즘의 공식 구현이다. 명암 대비가 톤 단위로 보장된다 |
| 애니메이션 | ① **Svelte 내장** `transition` · `animate:flip` · `crossfade` · `Spring` ② 화면 전환은 **View Transitions API** ③ 연출이 긴 시퀀스(딜, 결과 연출)만 **Motion(motion.dev) `animate()`** | 대부분은 의존성 없이 내장으로 끝낸다. 무거운 라이브러리는 필요한 곳에만 쓴다 |
| 아이콘·글꼴 | **Material Symbols Rounded**(가변 폰트, 쓰는 아이콘만 서브셋) · **Pretendard Variable**(한글) | M3 아이콘과 한국어 가독성 |

| 품질 게이트 | 기존 Playwright 스모크 + **Lighthouse CI** + 프레임 측정 | 예쁜데 느려지는 것을 CI에서 막는다 |

## 2. 후보 비교

평가 기준: **성능**(번들·런타임·애니메이션), **개발 속도**, **M3 충실도**, **게임 화면 적합성**(카드 이동·드래그·동시 애니메이션)

| 조합 | 성능 | 개발 속도 | M3 충실도 | 게임 적합 | 판단 |
|---|---|---|---|---|---|
| **A. Svelte 5 + 자체 M3 키트 + Svelte 전환/Spring + View Transitions (+Motion 일부)** | ◎ 런타임 최소 | ◎ 컴포넌트 문법 간결, 전환 내장 | ○ 토큰·스펙을 직접 따라야 함 | ◎ `crossfade`로 컨테이너 간 카드 이동, `flip`으로 손패 정렬 | **채택** |
| B. 바닐라 유지 + **mdui**(M3 웹 컴포넌트) + Motion | ○ | ○ 프레임워크 교체 없음 | ○ M3 컴포넌트 다수 제공 | △ 상태가 많은 게임 화면은 지금처럼 수동 DOM 갱신 | 빠른 대안. 대규모 개편엔 유지보수 부담 |
| C. 바닐라 + Material Web(@material/web) | ○ | ○ | ◎ 공식 M3(Expressive 이전) | △ | **비추천**: 유지보수 모드, 신규 기능 중단 |
| D. React + MUI + Motion(React) | △ 런타임·번들 큼 | ◎ 생태계 최대 | △ MUI는 M3 완전 대응 아님 | ○ `layout`/`layoutId` 강력 | 무게 대비 이득 적음 |
| E. Vue 3 + Vuetify 3(md3 블루프린트) | △ | ○ | ○ | ○ | 컴포넌트는 많지만 번들 큼 |
| F. Flutter Web (M3 Expressive 네이티브) | ✕ 초기 로드 수 MB, 캔버스 렌더 | ○ | ◎ | ○ | 웹 성능·텍스트 품질 손해. 비추천 |

**A를 고른 이유를 한 문장으로**: 이 앱의 무게는 엔진(WASM)과 카드 애니메이션에 있다. UI 층은 가장 얇고 빠른 것이 좋고, Svelte는 카드가 컨테이너 사이를 날아다니는 연출(`crossfade` + `flip`)을 코드 몇 줄로 제공한다.

## 3. 디자인 시스템 (M3 토큰)

모든 값은 CSS 사용자 속성 `--md-sys-*`로 둔다. 컴포넌트는 토큰만 참조한다.

### 3.1 색
- **시드 색**: 테이블 펠트 그린(현재 `#1f6f50` 계열) → material-color-utilities `SchemeTonalSpot`(기본) / `SchemeExpressive`(설정에서 선택).
- **역할 매핑**
  - `primary`: 주요 행동(받기, 버리기, 새 판)
  - `secondary`: 보조(같은 패 다시, 되돌리기)
  - `tertiary`: 금색 계열 강조(내 차례, 선택 카드, 장수 경고)
  - `error`: 스톱, 블런더, 규칙 위반 안내
  - `surface-container-*`: 패널·카드 배경(낮음→높음)
  - 테이블 펠트: `primary-container` 계열을 깊게 쓴 전용 표면
- **고정 색(테마를 따르지 않음)**: 카드 앞면(크림), 하트·다이아 빨강, 카드 뒷면. 게임 판독성이 우선이다.
- **다크 모드**: 같은 팔레트에서 다크 스킴을 뽑는다(자동 반전 아님). 고대비 스킴도 함께 제공한다.
- **복기 등급색**: M3 역할과 분리된 상태 팔레트(최선·좋음 / 부정확 / 실수 / 블런더)를 유지하고, 항상 아이콘과 라벨을 함께 붙인다.

### 3.2 타이포그래피
- M3 타입 스케일(Display / Headline / Title / Body / Label × L·M·S)을 **Pretendard Variable**에 매핑한다.
- 점수·장수·승률은 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다.

### 3.3 모양(Shape)
- M3 코너 스케일: extra-small 4 · small 8 · medium 12 · large 16 · extra-large 28 · full.
- 카드 패 = medium(12), 시트·다이얼로그 = extra-large(28), 버튼·칩 = full. 선택 상태에서는 Expressive식 **모양 모핑**(코너가 둥글게 변함)을 쓴다.

### 3.4 높이(Elevation)
- 그림자보다 **톤(표면 컨테이너 단계)** 으로 층을 나눈다. 그림자는 손에 든 카드와 끌고 있는 카드에만 쓴다.

### 3.5 모션
- **M3 Expressive 모션 스킴**을 따른다. 위치·크기 이동은 **공간(spatial) 스프링**, 색·투명도는 **효과(effects) 스프링**이다. 수치는 구현할 때 공식 토큰 표로 고정한다.
- 원칙: `transform`과 `opacity`만 애니메이션한다(레이아웃 재계산 없음). 동시에 움직이는 요소는 12개 이하로 둔다. `prefers-reduced-motion`이면 즉시 전환으로 대체한다.
- 상태 레이어: hover 8% · focus 10% · pressed 10% · dragged 16% 오버레이, 리플은 pressed에만.

## 5. 화면별 설계

### 5.1 대전 (모바일 기준)
```
┌──────────────────────────────┐
│ Top app bar   훌라   ⋮        │
├──────────────────────────────┤
│ [상대 좌석 카드]  7장 · 등록    │  ← surface-container, 차례면 tertiary 테두리 + 펄스
│  방금 · 버림 K♦                │
├──────────────────────────────┤
│   펠트 테이블                   │
│   [더미] [버림패]  [바닥 조합…] │  ← 조합은 칩처럼 묶임, 붙이기 대상이면 강조
├──────────────────────────────┤
│ 내 손패  23점      (기준표 칩)  │
│ [카드][카드][카드]…  (부채꼴)   │  ← 선택하면 위로 올라오고 코너 모핑
│ [스톱]  [땡큐]  [등록]  ( 받기 ) │  ← 받기 = Extended FAB, 스톱 = error tonal
├──────────────────────────────┤
│  대전 · 훈련 · 기록  (Nav bar) │
└──────────────────────────────┘
```
- **카드 모션**
  - 받기: 더미에서 손패 자리로 **crossfade 비행** 후 손패 `flip` 재정렬
  - 버리기: 손패에서 버림패로 비행. 이전 맨 위 카드는 아래로 깔린다
  - 등록: 고른 카드들이 바닥으로 함께 이동해 조합 그룹으로 모인다
  - 붙이기: 카드 1장을 고르면 붙일 수 있는 조합이 강조되고, 누르면 그 조합으로 이동
  - 봇의 행동도 같은 모션을 짧게 재생한다(기록 패널과 연동)
- **PC/태블릿**: Navigation rail + 오른쪽 보조 패널(기록·힌트·전적)

### 5.2 훈련
- 홈: Hero 카드(오늘의 훈련 Extended FAB) + 드릴 카드 그리드(정답률 진행 막대) + 오답 노트 배지
- 문제: 상단 linear progress(정답/오답 점), 장면 컴포넌트 재사용, 하단 고정 행동 바
- 피드백: **바닥에서 올라오는 standard bottom sheet**(정답 primary-container / 오답 error-container), "다음 문제" FAB. 정답이면 짧은 스프링 바운스로 보상한다

### 5.3 복기
- full-screen dialog. 상단은 요약 칩 4개, 그다음 승률 흐름 그래프(기존 데이터 시각화 규칙 유지)
- 목록과 상세는 반응형 2단 / 1단. 상세의 "장면"은 대전과 같은 컴포넌트를 써서 내 수(error)와 추천(primary)을 카드 위에 표시한다

### 5.4 기록(전적·약점)
- 상대 구성별 승률 카드(공평한 몫 기준선), 약점 유형 막대, 훈련 일별 기록(작은 막대 차트)

## 6. UX 설계 — 쉽고 편하게 모든 기능을 쓰게

지금 연습장의 불편한 점(현재 화면 기준)
- 행동 버튼의 위치와 개수가 단계마다 바뀌어서, 매번 버튼을 다시 찾아야 한다.
- 스톱 판단에 가장 중요한 **상대 손패 장수**가 작게 보이고, 기록·전적 같은 보조 정보와 같은 무게로 보인다.
- 복기, 훈련, 오답 노트가 서로 연결돼 있다는 사실이 화면에서 드러나지 않는다(결과 창 → 복기 → 훈련 흐름이 끊김).
- 설정은 한 패널에 몰려 있고, 처음 온 사람을 위한 안내가 없다.

### 6.1 원칙 (모든 화면 공통)

1. **한 순간에 주 행동은 하나.** 지금 가장 할 법한 행동 하나만 Filled 버튼이나 FAB로 둔다(받기 / 버리기 / 다음 문제 / 복기하기). 나머지는 Tonal·Outlined.
2. **엄지 영역.** 휴대폰에서는 게임 조작을 전부 화면 아래 1/3(내 손패 + 행동 바)에 둔다. 위쪽은 보는 정보만 둔다.
3. **고정 슬롯.** 행동 바의 버튼 자리는 단계가 바뀌어도 움직이지 않는다. 왼쪽부터 `[스톱] [땡큐] [등록] [붙이기] … [주 행동]` 순서다. 지금 못 하는 행동은 숨기지 않고 비활성으로 둔다(셀프 모드에서도 위치는 같고, 누르면 규칙 안내가 나온다).
4. **직접 조작 + 버튼 둘 다.** 카드를 탭하면 선택된다. 끌어서 버림패에 놓으면 버리기, 바닥 조합에 놓으면 붙이기, 두 번 탭하면 버리기다. 같은 일을 버튼으로도 할 수 있다(정확성과 접근성).
5. **정보 위계.** 크기와 위치를 중요도 순서로 정한다.
   1. 내 차례 여부, 내 손패 점수 (가장 크게)
   2. 상대 손패 장수 (스톱 판단의 핵심. 3장 이하면 tertiary 색 경고)
   3. 버림패 맨 위 (땡큐 판단)
   4. 바닥 조합 (붙이기 판단)
   5. 기록·전적·힌트 (접어 두는 보조 패널)
6. **무엇이든 되돌릴 수 있다.** 내 행동 직후 스낵바에 "되돌리기" 액션을 띄운다. 상단 되돌리기 버튼도 유지한다.
7. **실수 예방은 모드에 맞춰.** 셀프 모드는 실전처럼 확인 창 없이 바로 진행한다. 초보자 모드에서는 기준표와 다른 스톱일 때 버튼 옆에 "기준표: 기다림" 칩을 보여 준다(막지는 않는다).
8. **즉각 반응.** 모든 탭은 100ms 안에 상태 레이어로 반응한다. 봇의 행동은 해당 좌석 하이라이트와 짧은 카드 이동으로 보여 주고, 기록에도 남긴다.

### 6.2 내비게이션과 기능 흐름

- **3개 목적지**: `대전` · `훈련` · `기록` (휴대폰은 Navigation bar, 태블릿·PC는 Navigation rail). 설정은 상단 앱 바의 아이콘에 둔다.
- **순환 흐름을 화면에 드러낸다.**
  - 판 종료 시트: 결과 → 주 행동 **"복기하기"**, 보조 "같은 패 다시" · "새 판"
  - 복기 화면 끝: **"이 실수 훈련하기"**(해당 유형 훈련으로 바로) · "이 장면부터 다시 두기"
  - 훈련 홈: 오답 노트 배지(대기 수)와 "최근 복기에서 온 문제" 표시
  - 기록: 약점 막대를 누르면 그 유형 훈련 시작
- **새 판 시트.** "새 판"을 누르면 바텀 시트가 열린다. 자주 바꾸는 것(인원, 상대 프리셋, 모드)만 보여 주고 바로 시작한다. 세부 설정(봇 속도, 버림패 공개, 시드)은 펼침 영역에 둔다.
- **상대 프리셋.** "친구", "고수", "초보", "직접" 칩으로 고른다(현재 드롭다운 대체). 고르면 한 줄 설명이 나오고, 처음 기본값은 "친구"다.
- **봇 이름 (D5).** 두세 글자로 통일하고 모음으로 끝낸다("1번 고수가 털었다"). 저장 키는 전적 호환을 위해 그대로 둔다. `friendE` 친구 · `expert` 고수 · `greedy` 초보 · `friendA` 버티기 · `friendB` 승부사 · `friendC` 잠수. Random은 목록에서 뺐다: 저장된 설정은 초보로 바뀌고, 지난 전적에는 "무작위"로 남는다. 엔진의 `random` 사양과 기존 앱(`web/`)은 그대로이므로, 교체할 때 `README.md`·`STRATEGY.md`·`TRAINING.md`의 옛 이름도 함께 바꾼다.

### 6.3 화면 표시 세부

- **내 손패**: 무늬·숫자 순으로 정렬한다(정렬 방식 토글 제공). 선택한 카드는 위로 올라오고 테두리가 생긴다. 셀프 모드에서는 카드를 고르면 행동 바의 해당 버튼에 선택 미리보기가 뜬다("등록 5♠ 5♥ 5♦").
- **상대 좌석**: 이름, 장수(큰 숫자), 등록 여부, 방금 한 행동 한 줄. 차례면 테두리가 펄스한다. 좌석을 누르거나 마우스를 올리면 그 봇의 특징을 말풍선으로 보여 준다.
- **스톱 영역**: 초보자 모드는 행동 바 위에 기준표 칩("상대 최소 3장 → 8점 이하")을 띄운다. 셀프 모드는 아무것도 띄우지 않는다.
- **규칙 안내**: 지금의 빨간 상자 대신 스낵바를 쓴다. 한 줄 요약에 "규칙 보기" 액션을 붙인다.
- **기록 패널**: 휴대폰은 접힌 시트(최근 3줄 미리보기), PC는 오른쪽 패널이다.
- **판 종료 시트**: 승패를 크게 보여 주고, 전원 손패와 점수, 끝난 이유("상대 털기 · 내 손패 14점")를 표시한다. 졌을 때는 한 줄 원인 추정("10점 이하가 되기 전에 상대가 털었다 → 훈련: 조합 찾기")을 붙인다.
- **빈 상태**: 전적이 없거나 오답 노트가 비었을 때 "첫 판 시작" 같은 다음 행동 버튼을 보여 준다.

### 6.4 처음 쓰는 사람

- **첫 실행 코치마크 3단계**: ① 내 손패와 점수 ② 상대 장수 ③ 행동 바. 언제든 앱 바의 `?`로 다시 볼 수 있다.
- **규칙 30초 요약 시트**: 조합 3종, 땡큐, 스톱(1금 2-4 3-8 4-10), 털기. 그림 카드 예시 포함.
- 처음 3판은 초보자 모드를 권하는 칩을 띄운다(강제하지 않음).

### 6.5 접근성

- 색만으로 구분하지 않는다(아이콘·라벨 병행). 본문 대비 4.5:1 이상.
- 글자 200% 확대까지 레이아웃이 깨지지 않는다. 터치 영역은 48dp 이상이다.
- 스크린 리더: 카드 `aria-label`("하트 10"), 라이브 영역 알림("상대가 다이아 K를 버렸다", "내 차례").
- 키보드: 카드 이동(←/→), 선택(Space), 행동 단축키(D 받기, T 땡큐, R 등록, S 스톱), Enter 주 행동.

Lighthouse 6개 경로 3회 모두 성능 1.0, 접근성·모범사례 1.0(중앙값), `/motion` LCP 3.3s 이상값은 재발하지 않음(3회 1.21s). 이전 실행보다 중앙값 TBT `/theme` 8→60ms·`/gallery` 0→25ms, CLS `/gallery` 0.013→0.026으로 늘었으나 기준 안이다. 페이지 JS는 변화 없음(판 시작 후 63.6KB), 서비스 워커 파일은 별도로 3.0KB(gzip). 구성: `manifest.webmanifest`(standalone), 아이콘 192·512(일반·maskable)와 iOS 180, 파비콘 교체. 업데이트는 `skipWaiting` 없이 앱을 모두 닫았다 다시 열 때 적용한다(판 도중 옛 지연 로드 묶음을 잃지 않게). 글꼴 캐시는 `Vary: Origin` 때문에 오프라인에서 전부 빗나가던 것을 E2E에서 잡아 `ignoreVary`로 고쳤다. `main` 배포(run 42352875966) 뒤 배포 주소에서 매니페스트·서비스 워커·오프라인 판 시작을 확인했고, 프로젝트 소유자의 실기기 설치·오프라인 테스트도 통과했다. 실제 버전 교체 흐름은 아직 확인하지 못했다. 360px CLS의 원인은 글꼴 교체 때 달라지는 줄바꿈이었다. 문구를 정리해 로컬 측정 `/` 0.032→0.004, `/train` 0.020→0, `/records` 0.010→0으로 줄이고 E2E를 추가했다(개발용 `/gallery`는 약 0.10 남음). 휴리스틱 평가는 [HEURISTICS.md](HEURISTICS.md)에 기록했다. 엔진 로드 실패가 캐시되어 재시도할 수 없던 버그 등을 고쳤다. 남은 일: 진행 중인 판 복원(심각도 3), 글자 크기 `rem` 전환(심각도 2)의 진행 여부 결정, 정식 교체** |

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| Svelte용 M3 완성 키트가 없음 | 필요한 15개 남짓만 직접 만든다. 다이얼로그·시트는 `<dialog>`(포커스 가두기·Esc·포커스 복귀 내장), 메뉴는 `popover` API를 쓴다 (D2에서 Bits UI 대신 채택: 날짜 라이브러리 의존성 없이 더 가볍다) |
| M3 Expressive 웹 공식 구현 부재 | 스펙(토큰·모션 스킴)을 직접 구현한다. 수치는 공식 문서 값으로 고정하고, 갤러리 페이지에서 시각 확인 |
| 애니메이션 때문에 판 진행이 느려짐 | 봇 속도 설정과 모션 길이를 연동한다(빠르게 = 모션 축약). 연습 효율이 우선 |
| `crossfade`는 두 카드를 함께 흐리게 해 비행 중 카드가 비쳐 보임 | D3에서 같은 구조의 `send`/`receive`를 직접 만들어 쓴다(`lib/game/motion.svelte.ts`). 카드는 불투명하게 날고, 안 보이던 곳(더미·봇 좌석)에서도 날아온다 |
| 저사양 휴대폰 성능 | 동시 모션 상한, 그림자 최소화, 모션 줄이기 자동 감지 |
| 교체 중 회귀 | 기존 Playwright 스모크를 새 앱에도 그대로 돌리고, 통과 전에는 교체하지 않는다 |
