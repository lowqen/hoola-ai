# 휴리스틱 평가 (D5, 2026-11-07)

`/hoola-ai/next/`를 Nielsen 10원칙으로 점검한 기록이다. 평가자는 개발 도구(Claude) 혼자이고, 360px 화면 캡처, 코드, E2E로 확인했다. 실사용자 관찰이 아니므로 사용자 테스트를 대신하지 않는다.

심각도: 3 = 큰 문제, 2 = 중간, 1 = 사소함.

## 열린 문제

| # | 심각도 | 원칙 | 문제 | 제안 |

| 7 | 1 | 4 일관성 | `/gallery`는 360px에서 CLS 0.10이 남아 있다. 개발용 화면이라 사용자 영향은 없다 | 정식 교체 때 공개 범위와 함께 결정 |

## 이번에 고친 것

| 원칙 | 문제 | 조치 |
|---|---|---|
| 3 사용자 제어, 5 오류 예방 | 진행 중인 판이 저장되지 않아 새로고침하면 사라졌다(심각도 3) | 행동마다 리플레이를 별도 키(`hoola-practice-game-v1`)에 저장하고, 첫 화면을 열 때 자동 복원. 저장을 읽을 수 없으면 버린다. E2E 추가 |
| 9 오류 복구 | 엔진 로드가 한 번 실패하면 실패한 Promise가 남아 새로고침 전까지 시작할 수 없었다 | 실패를 캐시하지 않음. 재시도 E2E 추가 |
| 9 오류 복구 | 로드 실패 때 오류 원문을 그대로 보여 줬다 | "게임을 불러오지 못했다. 연결을 확인하고 다시 눌러 보세요."로 교체 |
| 4 일관성 | 설명문에 "~습니다"가 섞여 있었다. 안내는 "~세요", 설명은 "~다"로 맞춤 | 훈련 문구 2곳 수정 |
| 4 일관성 | 기록의 약점 빈 안내만 11px였다 | 옆 카드와 같은 본문 크기·문장 형식으로 변경 |
| 4 일관성 | 360px에서 글꼴이 바뀌면 줄 수가 달라져 화면이 밀렸다 | 문구 정리, 360px CLS E2E 추가 |

|---|---|---|
| 1. 상태 표시 | 양호 | "내 차례"/"N번 친구 차례", 손패 점수, 더미 장수, 라이브 영역 알림. 열린 문제 3, 6 |
| 2. 현실과의 일치 | 양호 | 받기·땡큐·스톱·털기 등 실제 게임 용어. 좌석 말풍선으로 봇 특징 설명 |

| 4. 일관성 | 양호 | M3 토큰, 고정 슬롯 행동 바, 프리셋 칩. 열린 문제 4 |

## 확인하지 못한 것

- 스크린 리더 실제 낭독과 OS 글자 크기 설정의 실기기 동작
- 복기 화면과 훈련 문제 풀이는 이번 캡처로 보지 않았다(E2E 통과만 확인)
- 실제 사용자 관찰. §6.6의 실사용 피드백은 프로젝트 소유자의 실기기 PWA·오프라인 테스트 통과까지 받았다
